# 🔝 Top 10 Improvements (Highest Impact First)

1. **Printer configs are merged, not replaced, when switching printers**
   - **Category:** correctness
   - **Why it matters:** Switching printers merges the new config over the old one, so any field the response omits keeps the *previous* printer's value, while the initial load replaces. Restoration now depends on the config accurately describing the selected printer: `applySavedProperties` validates a saved tray or resolution against capability arrays that may have been inherited from the printer looked at before.
   - **Evidence:** `src/components/ezp-printer-selection/ezp-printer-selection.tsx:539` (merge) vs `src/components/ezp-printer-selection/ezp-printer-selection.tsx:764` (replace); consumer `src/utils/printer.ts:73-130`
   - **Action:** *Confirm `GetPrinterProperties` always returns every capability field; if it can omit them, replace the config instead of merging.*

2. **Print settings outlive logout and are shared by everyone on the browser profile**
   - **Category:** compliance
   - **Why it matters:** `clearSession()` no longer removes the saved printer or settings, as the ticket requires ("not deleted on logout", "stored per browser profile"). On a shared or kiosk machine the next user to sign in inherits the previous user's paper size, tray and colour for any printer they both have, and the previous printer's name stays in `localStorage` after logout. The selection itself resets when the printer is absent from the new user's list, so nothing unusable is preselected.
   - **Evidence:** `src/shared/storage.ts:80-92`, `src/components/ezp-printer-selection/ezp-printer-selection.tsx:492-515`
   - **Action:** *Confirm with product/privacy; if unwanted, key the settings map by user id.*

3. **A failed print still rewrites the remembered settings**
   - **Category:** correctness
   - **Why it matters:** `rememberSelection()` runs after the try/catch, so a failed job still makes that printer and its settings the preselection next time. This matches the previous behaviour exactly (the old `setProperties`/`setPrinter` sat on the same line) and is arguably right, but it does mean a misbehaving printer keeps returning preselected.
   - **Evidence:** `src/components/ezp-printer-selection/ezp-printer-selection.tsx:455-480`
   - **Action:** *Decide whether remembering should depend on a successful job.*

4. **`ezp-file-name` reads `ezp-label`'s shadow DOM to decide whether to show a tooltip**
   - **Category:** maintainability
   - **Why it matters:** The tooltip only opens when the name is really clipped, a measurement only the label can make. `isTruncated()` is a proper public method, but the caller still queries `.head` and depends on the label rendering `#text`. If that internal id changes, tooltips silently stop appearing — a regression specs on a spec page will not catch.
   - **Evidence:** `src/components/ezp-file-name/ezp-file-name.tsx:95-102`, `src/components/ezp-label/ezp-label.tsx:11-27`
   - **Action:** *Acceptable as is; if `ezp-label` is refactored, keep `#text` or update both sides together.*

5. **Tooltip placement relies on the consumer setting `position: relative`**
   - **Category:** maintainability
   - **Why it matters:** `:host` is deliberately not a positioning context so the bubble can span the whole row instead of the narrow name column. Both consumers set it, but nothing enforces it — a third consumer would get a tooltip anchored to a distant ancestor.
   - **Evidence:** `src/components/ezp-file-name/ezp-file-name.scss:7-10`, `src/components/ezp-upload/ezp-upload.scss:183-184`, `src/components/ezp-printer-selection/ezp-printer-selection.scss:145-146`
   - **Action:** *Document the contract in `ezp-file-name/readme.md` before the component is reused.*

6. **Branch coverage dipped on the two files carrying the new logic**
   - **Category:** tests
   - **Why it matters:** Overall branch coverage rose (46.70% → 51.88%), but `storage.ts` fell 100% → 92.31% and `utils/printer.ts` 96.15% → 92.44%, because the new conditionals add paths no test reaches: the migration's "legacy blob without a saved printer" case and several capability guards.
   - **Evidence:** `src/shared/storage.ts:110`, `src/utils/printer.ts:90,103-107,112`
   - **Action:** *Add a case for a legacy blob with no saved printer, and for a saved tray on a printer reporting no trays.*

7. **Middle truncation leaves a one-character gap before the tail**
   - **Category:** documentation
   - **Why it matters:** `Quarterly_Report_202… l_DE.pdf` — inherent to the CSS technique: the clipped box is sized to the available width and the browser truncates on a character boundary, leaving up to one character of slack, which can read as a space inside the name. Measured rather than assumed: the tail starts exactly where the head box ends, so no stray margin is involved.
   - **Evidence:** `src/components/ezp-file-name/ezp-file-name.scss:33-43`
   - **Action:** *Accept, or truncate with JS text measurement (canvas/Range + ResizeObserver) if design objects.*

8. **`TAIL_LENGTH` is a fixed 8 characters**
   - **Category:** maintainability
   - **Why it matters:** Chosen to cover suffixes like `_DE.pdf`. Files diverging further back (`…_v2_final_DE.pdf`) still look identical until hovered.
   - **Evidence:** `src/components/ezp-file-name/ezp-file-name.tsx:9`
   - **Action:** *Raise the constant if real file names need it.*

9. **The pre-upgrade `properties` key is never cleaned up**
   - **Category:** maintainability
   - **Why it matters:** The migration reads the old blob on every call until the first write lands, and the legacy key then stays in `localStorage` indefinitely. Harmless in size, but permanent.
   - **Evidence:** `src/shared/storage.ts:104-115`
   - **Action:** *Optionally remove the legacy key once the map has been written.*

10. **`setDefaultPaperFormat()`'s guard cannot fire**
    - **Category:** correctness
    - **Why it matters:** It runs only when `paper === ''`, but the defaults set `paper` to `undefined` when no format is flagged default, so the locale-based A4/Letter fallback never executes. Pre-existing and unchanged here, but it looks like a safety net that isn't one.
    - **Evidence:** `src/components/ezp-printer-selection/ezp-printer-selection.tsx:770-772`, `src/utils/printer.ts:46-48`
    - **Action:** *Compare against `!paper` if the fallback is meant to work.*

No further significant issues detected.
